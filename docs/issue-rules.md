# 이슈 판정 규칙

접수된 이슈의 유형과 우선순위를 정하는 기준입니다.
사람이 판정할 때도, 스크립트로 판정할 때도 이 문서를 따릅니다.

## 유형

제목과 내용에서 아래 키워드를 찾아 유형을 정합니다.
여러 유형에 해당하면 위에 있는 유형이 우선합니다.

| 유형 | 키워드 |
| --- | --- |
| 버그 | 오류, 실패, 멈춤, 끊김, 고정, 안 됨, 안됨, 튐, 튀는, 깨짐, 가득, 만료, 손실 |
| 기능요청 | 추가, 지원, 개선, 옵션 |
| 문의 | 문의, 방법, 어떻게, 절차 |
| 기타 | 위 키워드가 하나도 없는 경우 |

## 우선순위

| 우선순위 | 조건 |
| --- | --- |
| 높음 | 버그이면서 제목이나 내용에 양산, 고객, 전체, 데이터 손실, 안전 중 하나가 있는 경우 |
| 중간 | 그 밖의 버그 |
| 낮음 | 기능요청, 문의, 기타 |

## 미판정과 별도 표기

판정 근거가 부족하거나 값이 이상한 항목은 사람이 확인해야 합니다.
아래 조건에 해당하면 판정을 멈추거나 비고에 표기합니다.

| 상황 | 처리 | 비고 표기 |
| --- | --- | --- |
| 내용이 15자 미만 | 미판정 | 근거 부족 |
| 유형이 기타 | 미판정 | 유형 불명 |
| 버그이지만 내용에 가끔, 모르, 불규칙 중 하나가 있는 경우 | 미판정 | 재현 조건 없음 |
| 접수일이 YYYY-MM-DD 형식이 아니거나 실제 날짜가 아닌 경우 | 판정은 진행 | 접수일 형식 오류 |
| 접수일이 오늘보다 미래인 경우 | 판정은 진행 | 접수일 미래 |

## 담당자 배정

| 조건 | 담당 |
| --- | --- |
| 우선순위 높음 | 파트장 |
| 버그 | 개발 파트 |
| 기능요청 | 기획 파트 |
| 문의 | 기술지원 파트 |
| 미판정 | 접수자에게 재확인 요청 |
